# Java backend implementation — 2026-10-09

Java now has a compilable Spring Boot application under `backend/`; this does not mean it is deployed or that real RabbitMQ exchange traffic has passed integration acceptance. The former FastAPI workbench remains available as the transition implementation.

Implemented responsibilities:

- `/api/v1/admissions`, `/version`, `/institutions`: read only the existing immutable MySQL public projection and current head. Independently hash exact canonical bytes from the additive `admissions_publication_bytes` archive and compare JSON numeric meaning with the query projection. Optional Redis cache also must satisfy `SHA256(body)==version` and falls back to MySQL.
- `/dashboard`, `/heat`, `/recommendations`, `/game-scenario` and `/admissions/compare`: call bounded Python internal HTTP with the private internal token. Requests referring to changed data return 409; unknown heat units are rejected before an internal call.
- `/admissions/comparisons` list/save/read/export: reuse immutable records in existing `personal_comparison`, preserve Python canonical result bytes and validate the archive SHA independently. Java contains no school scoring or game formula.
- `/tasks`, `/{id}`, `/{id}/result`, `/{id}/cancel`: JDBC task/outbox transaction, client-request idempotency, cooperative cancellation, persisted task status. Polling is the initial reliable frontend channel; SSE is not claimed implemented.
- Rabbit AMQP durable topology, persistent mandatory commands, positive publisher confirm with no returned message, leased outbox retry, inbox deduplication, version/attempt/processor/sequence checks and exact result-byte verification. Stopped attempts cannot resume through a late event. Valid stored facts and old publications are not overwritten.

The additive migration is `crawler/sql/009_application_messaging.sql`, frozen at SHA256 `1dff922cefbc25eb6a8772bb59f8c110b5b756331c31e4ceafd8131da5f81829`. Existing migrations 002–008 were not edited. Java owns `app_task/app_outbox/app_inbox`; Python owns `python_worker_execution/python_worker_result/python_event_outbox` and exact admissions publication bytes. No migration is automatically applied on Java boot. Default messaging and persistent writes are disabled pending private runtime configuration.

Build was actually run with local Java 23.0.1 and Maven 3.9.9, using Java release 21 and Spring Boot 4.1.1 BOM. Official Boot requirements list Java 17–26 and Maven 3.6.3+: [Spring Boot system requirements](https://docs.spring.io/spring-boot/system-requirements.html). Confirm/return behavior follows [Spring AMQP official reference](https://docs.spring.io/spring-amqp/reference/amqp/template.html); the tests separately verify positive confirm, returned command rejection, ACK after processing and transient NACK. Delivery is at least once plus business idempotency, not exactly once.

Synthetic tests cover transaction rollback if outbox insert fails, same request/different input rejection, publisher failure retaining the outbox, lease recovery and stale publisher rejection, duplicate/late state events, pause protection, result-before-success validation, cooperative cancellation, exact comparison float bytes and corruption detection, source-bearing public projection rejection, actual HTTP input/version checks and internal token behavior. HTTP tests use ephemeral loopback ports and H2; these are not evidence of VM RabbitMQ/MySQL integration. Root coordinates the separate real integration and deployment stages.

`mvn -q -f backend/pom.xml verify` passed: **19 tests**, with 11 transaction/storage tests, 2 AMQP semantic tests and 6 actual temporary HTTP tests. This also packaged `backend/target/gradheat-backend-0.1.0.jar`. The new exact publication test verifies both `1e-07` versus `0.0000001` and `1.0` versus `1`, while changed values and changed canonical bytes fail integrity checks. No actual VM data, migration, Rabbit command or Chrome request was issued by this agent.

Known boundary: archived comparisons with `result_bytes=NULL` require a separately verified Python backfill for complete scientific-notation compatibility; a Java reconstruction that changes bytes cannot be presented as verified. The initial service is a private local workspace with same-origin checks, bounded JSON inputs and optional write token, not a multi-user authentication system. Task status uses reliable polling; SSE and transfer of the daily scheduler are future steps. Root handles real integration, launch configuration, deployment, migration application and Git submission.

## Vue packaging and integration follow-up

Maven now embeds `frontend/dist` directly into the application jar's `static/`, keeping generated resources out of Java source directories. Build order is `npm --prefix frontend ci`, `npm --prefix frontend run build`, then `mvn -f backend/pom.xml clean verify`. Vue HashRouter requires no server fallback route. Packaging fails clearly if the frontend production entry is missing. The Enforcer 3.6.3 file rule compares canonical URIs; the gate uses `project.basedir.parentFile` so an otherwise valid Windows `..` path does not cause a false missing-file error. No bypass of the gate was used.

Added `GET /api/v1/health`: Java liveness and verified-publication readiness are separate booleans, and no connection details appear. Public task results are restricted to approved `analyse.long` operations; collection/extraction/verification originals are not returned, and task status never includes scope paths. The source/private-field guard also rejects original artifact/transcript locations and raw document fields.

The actual module integration agent found uvicorn rejecting Java's default h2c upgrade. Java now explicitly selects HTTP/1.1, and the synthetic internal-bridge test asserts there is no `Upgrade` header. The original failed real integration report is retained by the module agent; recovery is not inferred from synthetic tests alone.

Follow-up `mvn -q -f backend/pom.xml test` passed **22 tests** (12 transaction/storage + 2 AMQP semantics + 8 temporary HTTP). `mvn -q -f backend/pom.xml package -DskipTests` passed and jar entries include `BOOT-INF/classes/static/index.html` and Vue assets. The module test agent was notified to use the updated jar for further real round trips. Migration 009 remains byte-for-byte frozen. This stage packages a deployable build; it does not by itself show that a persistent website has been launched.
