## 2. 先修正六个建模前提

### 2.1 录取者分数分布不能直接变成录取概率

`DESIGN.md:75` 将录取均分视为最有价值的单一指标，`:824` 将“估分分布 ∩ 录取分布”作为核心计算。这只能支持历史位置比较。

已录取者的分布是 `P(分数 | 已录取)`；考生需要的是 `P(录取 | 分数、个人能力、项目规则)`。二者不相同。缺少未录取者及其结果，无法知道同分考生究竟有多少人失败。

应优先联结复试名单、完整复试结果、拟录取名单及递补/撤销公告。只有拟录取名单时，展示历史分位数、样本量与适用范围，不输出个人成功概率或“保底”。

### 2.2 同卷提供比较基础，但不等于跨校、跨年完全等价

同年同科目组合可以比较初试成绩，但录取机制、候选人自选择和复试要求仍不同。跨年还存在试卷难度等共同变化。当前材料不足以对任何“地区评分差异”赋予固定修正分，也不应凭传言设定。

保留原始分数；同时呈现相同科目组合、相同年度、明确参照项目集下的相对位置。参照集的组成与覆盖变化必须留档。国家线可作背景变量，不能当成精确的年度难度换算表。

### 2.3 三年序列不构成大小年识别的充分条件

三年只有两次年度变化，无法可靠区分周期、偶然波动、计划变化与考试共同冲击。改成“历史少时仅描述；是否启用行为修正取决于跨年度、跨项目验证”。

`DESIGN.md:187` 的“波动大 → 博弈主导”、`:189` 的“低分位 = 洼地”都应改成待检验解释。波动是观察，原因需要额外证据。年份更多也不能自动证明周期。

### 2.4 完整度、证据质量和预测不确定性应分开

`DESIGN.md:700` 的 coverage 是字段覆盖率，不是预测正确率。来源权重 1.0 / 0.9 / 0.7 / 0.4 同样不是经验证的概率。

分别报告：数据覆盖率、关键字段是否核验、口径是否明确、样本量与缺失比例、规则有效期、模型区间与验证表现。原始事实不因来源较低而乘 0.7；来源等级用于决定采用、冲突处理和展示资格。

官方公众号发布自身招生公告可以是一手来源；机构转载官网仍与官网属于同一来源链。两个网址并不一定是独立交叉验证，唯一的官方原始名单也不因只有一个网址就天然不可靠。

### 2.5 关注度、竞争难度、个人适配需要独立展示

学校讨论多可能来自招生宣传、新闻、名称歧义或平台采样变化。不能直接换算报名人数，也不能与均分、复录比再重复加权为一个“难度真值”。

建议把输出拆为四块：历史竞争与名额、个人初试与复试适配、培养收益与成本、未来情景与证据质量。不同考生可以得到不同候选顺序。

### 2.6 反身性是需要考察的影响，不是确定的结局

“公开好考就一定不好考”“稳定必然导致拥挤”是行为假设。是否发生取决于传播范围、考生替代选择、名额与报考成本。保留反身性提醒，但不要把假设写成规律。

`PRIOR-ART.md:552`、`:576` 的“学术上无人做过”“我们是第一个”应改为“在已记录的检索范围内，尚未找到可直接验证并复用的实现”。没有检索到不能证明不存在。

## 3. 信息获取：围绕决策单元建立证据链

### 3.1 最小单元应是官方实际排名录取的竞争池

保留以下维度，再依据官方规则定义 `admission_pool_id`：招生单位、学院、专业、方向/项目、校区、学习方式、学位类型、普通/专项计划、报考类别、年度。

有的方向独立排名，有的合并排名；不能一律按方向拆，也不能一律按专业合。考试科目组合应记录到其实际生效层级，并保留 101/201/301/408 等代码、原文和确认状态。未知科目不能默认标成“不是 11408”。

先限定一志愿普通统考口径。推免、调剂、专项、单独考试、加分等另行标记；不把不同群体合在一起计算分数分布。

### 3.2 按决策价值安排采集顺序

| 优先级 | 信息 | 决策用途 |
|---|---|---|
| P0 | 目标年度目录、考试科目、报考资格、校区、学费学制 | 判断能否报、是否愿意去 |
| P0 | 计划总数、推免口径、明确公布的统考名额及修订 | 判断实际可竞争的席位 |
| P0 | 最近完成年度复试名单、完整成绩及结果、拟录取与递补 | 还原从入围到录取的过程 |
| P0 | 复试办法、成绩折算、合格线、排序与同分规则 | 识别个人适配和失败机制 |
| P1 | 前述历史资料，优先连续 3—5 年可比片段 | 描述变化与建立验证样本，非周期证明 |
| P1 | 改考、合并排名、计划调整、推免完成情况 | 标注结构变化，更新情景 |
| P2 | 同口径报名快照、招生意向与关注信号 | 辅助识别需求变化 |
| P2 | 就业/培养报告与可追溯经验材料 | 描述收益与培养体验，标明范围与缺失 |

“总计划减推免”只有在两者属于相同竞争池、相同年度与相同计划版本，而且其他占用项已明确时才成立。总计划可能已经不含推免；不能机械再减一次。拟接收推免与实际接收推免也必须区分。

一所学校建立研究生院、学院招生栏、专业目录、结果公示与更正公告的入口清单。搜索引擎负责发现，正式指标尽量回到原始文件。附件需要单独归档、计算内容哈希；网页未变不代表同 URL 的 PDF 未变。

官方公开平台对部分录取信息设置考生身份与报考范围权限，因此不能预设全国名单均可匿名直接抓取。见[研招网招生信息公开平台说明](https://yz.chsi.com.cn/zsgs/)。

### 3.3 每个字段都能追溯，每次变更都保留版本

建议数据管道：

```mermaid
flowchart LR
    A[官方入口与附件] --> B[不可变原文快照]
    B --> C[字段提取与证据定位]
    C --> D[口径核验与冲突处理]
    D --> E[按竞争池生成事实版本]
    E --> F[指标与历史验证]
    F --> G[个人情景比较]
    G --> H[优先补查影响选择的信息]
    H --> A
```

至少补齐以下实体，先由 JSONL 实现也可以，不要求一次建完全部表：

| 实体 | 核心内容 |
|---|---|
| `source_document` / `source_snapshot` | 发布主体、URL、附件关系、原文路径、原始哈希、发布日期、首次观测/抓取时间、修订关系 |
| `fact_observation` | 对象、字段、值/单位、统计口径、年份、证据页/表行、原文片段、解析器版本、复核状态 |
| `admission_pool` / `pool_version` | 官方竞争池定义、考试组合、排名规则、沿革映射、生效区间 |
| `quota_observation` | 计划/实际、总数/推免/统考/专项、公布时点、适用范围 |
| `candidate_stage_result` | 同年度同池内匿名关联键、初试各科、入围/到场/复试/拟录取/撤销状态、来源 |
| `admission_rule` | 权重、满分、单项合格线、同分排序、分组方式 |
| `metric_snapshot` | 指标版本、输入事实集合、口径、样本量、计算时间、缺失与冲突 |
| `decision_run` | 决策截至时间、画像版本、情景与参数、证据版本、输出理由 |

原始证据与对外展示分离；分析用匿名键联结即可，不需要在产品中展示考生姓名和完整编号。脱敏名单出现重号或无法唯一匹配时留“待确认”，不得强行联结。

### 3.4 质量门槛应绑定具体用途

事实状态至少区分：已核验、未披露、抓取失败、解析失败、口径不明、冲突、历史版本。NULL 保留，但不能只靠 NULL 表达所有原因。

关键校验包括：分数范围与总分一致性、名单跨页是否完整、重复行、招生池归属、名单与公告统计是否对得上、结果是否覆盖全部入围者、递补与撤销是否更新。招生未满或计划调整可以合法发生，数量不一致应进入复核而非强行改数。

人工或 LLM 提取均先进入待复核层。关键字段包括名额、分数、考试代码、年份、学习方式和身份类别；未通过规则校验与抽样原文检查，不进入正式指标。

## 4. 量化：先描述事实，再按证据能力升级

### 4.1 第一版应交付的指标

| 指标 | 计算与边界 |
|---|---|
| 初试门槛 | 官方总分/单科门槛，另列实际入围最低分；二者不混用 |
| 可竞争席位 | 同池普通统考一志愿可用计划；显示公布时点及口径 |
| 成绩分布 | 入围者与录取者分别计算 P25/P50/P75、范围、样本量 |
| 复试竞争 | 入围人数、实际到场人数、最终拟录取人数分别展示；比率注明分母 |
| 同分段结果 | 已明确结果且口径一致的参加复试者中，拟录取人数/人数；显示 n 与区间 |
| 排名变动 | 同池中初试排名与最终综合排名的变化；不把相关性当作“公平度” |
| 年度变化 | 名额变化、规则变化、参照组调整后的分数变化分别展示 |
| 证据充分性 | 关键证据状态、样本量、匹配率、截至日期；不揉成成功概率 |

完整结果中的“未录取”、未到场、主动放弃、复试不合格要分别记录。某人不在一份拟录取名单里，可能是后续递补、名单缺页或匹配失败，不能自动标为被刷。

同分段历史比例仅描述已进入复试的已观测群体。样本稀疏时可用 Wilson 区间或明确先验的 Beta-Binomial 描述不确定性；不能靠平滑制造缺失的失败样本，也不能把该比例直接外推为未来个人概率。

### 4.2 个人录取机会需要两阶段模型

用 `R` 表示获得复试资格，`A` 表示最终拟录取，`x` 表示个人信息，`j` 表示项目，`θ` 表示未来情景：

```text
P(A | x, j, θ)
  = P(R | x, j, θ) × P(A | R, x, j, θ)
```

这是条件概率分解，并不假设初试和复试相互独立。第一项需要估计个人各科成绩与未来入围规则/门槛；第二项需要完整结果、复试规则及个人复试能力。任一项无法可靠估计时，整体系数不应展示成确定的百分比。

建议按三档能力发布：

1. **历史对照档**：只有名单与规则，展示个人分数区间相对历年门槛的位置，不给录取概率。
2. **条件结果档**：有完整复试结果，展示“入围后、某分数段”的历史结果与区间，明确样本范围。
3. **概率模型档**：有跨年验证与校准，才给针对目标年度、明确假设下的概率区间。

复试制度确实会影响最终结果。教育部 2026 年管理规定明确综合初复试成绩择优录取、复试不合格不予录取；具体计算要解析院校办法。见[教育部规定](https://www.moe.gov.cn/srcsite/A15/moe_778/s3261/202509/t20250918_1413836.html)。例如[长江大学计算机学院 2026 年办法](https://jky.yangtzeu.edu.cn/info/1266/6293.htm)采用初试折算后 60%、复试 40%，并设置复试合格要求。这里仅说明模型必须支持的结构，不代表所有学校或未来年度采用相同规则。

### 4.3 个人输入应包括分科与误差来源

输入应包含目标入学年度、资格约束、近期多次模拟成绩及考试条件、四科薄弱项、机试/专业面试/英语能力、地域与方向、总成本、失败后备选路径。

不预设所有人的估分误差都是 ±10 或 ±15 分，也不未经检查就假设为正态分布。真题熟悉度、题目年份、模考难度与趋势都会影响误差。证据少时，用用户明确的低/中/高情景；数据足够时再估计经验分布。

模拟时保留科目间相关性，并使考生分数与学校门槛受到相同考试难度情景的影响。不要只把考生总分下调而让学校分数线保持不变，以免把共同难度变化误算成个人风险。

### 4.4 比较复试权重时，先统一量纲

示意：某规则为 `综合分 = 0.6 × 初试总分/5 + 0.4 × 复试百分制分数`。

初试领先 10 分折成综合分优势 1.2 分，复试落后 3 分就抵消这部分优势。这是规则敏感性计算，不是录取预测。比单独展示“复试占比 40%”更能帮助考生理解自己的优势。

## 5. 博弈：从解释故事改成可以验证的压力测试

### 5.1 区分供给变化、共同环境与行为反应

建议分别记录：

- 名额和机制：计划变化、推免完成情况、改考、排名池合并/拆分、复试规则。
- 共同环境：年度考试、参照项目整体变化；缺乏可靠指标时保留不确定性。
- 需求行为：往年难度、关注增量、同类替代项目变化、可比报名快照。

只有录取分数与名额时，无法唯一识别实际报名人数、考生能力分布和择校心理。不能通过拟合一条曲线就声称测出了“抄底弹性”。

招生选择可作为容量约束下的不完全信息拥挤博弈理解；蛛网机制是其中一种可能的滞后反应，并不意味着所有学校都服从周期。

### 5.2 第一版先比较明确情景

| 情景 | 可改变的参数 | 输出 |
|---|---|---|
| 规则延续 | 已知规则、最新可用名额，未知量保持范围 | 基准比较 |
| 席位收缩 | 普通统考名额减少 | 哪些个人分数情景开始失去优势 |
| 需求增强 | 报名规模或高分竞争者比例上升，明确为假设 | 对门槛与候选顺序的敏感性 |
| 替代项目变化 | 相近项目改考、扩招、城市/成本变化 | 哪些竞争池可能承接迁移；无证据不指定迁移量 |
| 个人发挥变化 | 分科成绩或复试发挥变化 | 哪个环节决定风险 |

没有证据为情景赋概率时，报告各情景结果，不把它们随意平均成“最终录取率”。压力幅度应由历史范围、官方变动或用户设定给出，标明来源；模拟数字必须标为模拟。

竞争迁移应在同科目、相近地域/层次/方向/成本的替代集合中研究。以后若使用离散选择或多主体模拟，只能先检验机制与参数敏感性；缺乏报名与意向数据时，不应将模拟人数视为真实估计。

### 5.3 热度信号进入模型前需要证明增量价值

采集时记录关键词消歧、平台、时间窗口、排序/截断规则、去重口径、查询版本和正常/失败状态。同一稿件的转载不能当作多个独立信号。

先比较两个模型：只用历史成绩、名额和规则的基线；在此基础上增加关注趋势的版本。只有新增信号在过去可获得信息条件下，稳定改善验证结果，才提高其决策权重。

站内浏览、收藏和意向仅代表平台用户，展示样本与变化；不直接外推全国报名数。产品传播可能影响选择，属于需要监测的反馈，不是用来免除验证的理由。

## 6. 院校选择：先过滤，再做偏好与风险权衡

推荐过程：

```text
资格/科目/学习方式/成本等硬约束
→ 历史证据可用性分档
→ 个人初试与复试适配
→ 培养价值与成本比较
→ 多情景压力测试
→ 候选集与最终选择理由
```

不要只最大化上岸概率。候选项目至少比较方向契合、地点、培养资源、可验证的就业信息、学费生活费、时间成本、个人失败损失。主观偏好由用户设定，缺失就业数据不能默认低质量，学校层级标签也不能代替全部收益。

当概率模型已具备验证基础，可用统一效用尺度表达：

```text
EU(j, θ) = p(j, θ) × U(录取到 j)
         + [1 - p(j, θ)] × U(报考 j 后未录取)
         - C(该选择带来的额外投入)
```

失败状态可以是工作、下一年再考或另走路径，不必为零。成本应明确哪些已包含在结果效用里，避免重复扣除。考前切换学校的额外准备成本也要考虑。当前产品若不做调剂，就只将失败后路径作为用户设定，不暗含“还能调剂保底”。

缺乏可信情景概率时，先保留在录取机会、培养价值、成本等维度不被全面压过的候选，再比较最差情景与最大后悔值：

```text
Regret(j, θ) = max_k U(k, θ) - U(j, θ)
选择规则示例：min_j max_θ Regret(j, θ)
```

这是一种偏保守的决策偏好，不能宣称适合所有人；应与追求期望收益的选择并列说明。情景集合也会影响结论，需让用户看见。

“冲/稳/保”如果保留，只表示针对个人的候选类别，不是可以同时报考的组合，也不是录取保证。第一版更建议用“门槛压力较大 / 历史匹配较好 / 证据不足”等具体描述。

最终院校卡片应回答：

- 哪些官方事实支持它适合我？
- 我的风险主要来自单科、总分、复试、席位还是未来需求？
- 哪个情景下它失去优势，届时更偏向哪一个候选？
- 哪条尚未明确的信息最值得先查？

最后一问形成采集闭环。例如两个项目选择主要取决于推免后的剩余名额，就优先核查名额公告；只有在多个合理情景下可能改变选择的信息，才值得投入更多获取成本。

## 7. 验证：用报名时能看到的信息评估后续结果

必须同时记录招生年度、实际考试时间、公开时间和采集时间。例如为某入学年度做前一年报名决策，输入只能使用该报名截至时间已公布的信息。次年复试线、最终统考录取数是结果，不能回填为当时已知特征。

回测建议按年度推进，并考虑项目分组：用较早年度训练，在后续完整年度测试。对新项目泛化另做留项目验证。不能把同一项目同一年度的考生随机拆开，就宣称预测了下一年的难度。时间数据的验证原则可参见 [scikit-learn 交叉验证文档](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-of-time-series-data)。

若历史文件是现在才采到，只有可靠的原始公开时间及修订证据才能进行历史可用信息重建；无法确认时标注为事后重建，不能宣称完全模拟当时可见信息。应从现在开始冻结真实决策快照。

| 检验层 | 建议验收内容 |
|---|---|
| 数据 | 对人工核验样本检查关键字段、跨页完整性、实体匹配和错误类别 |
| 门槛/分位数估计 | 与最近一年、简单近年基线比较误差及预测区间覆盖 |
| 录取概率 | 明确标签群体后检查 Brier score、校准曲线及样本区间 |
| 博弈增量 | 加入热度/行为变量后，相对基线有无稳定改进 |
| 决策 | 记录参数变化是否反转选择、失败原因与可解释性 |

概率校准需要比较预测概率与实际发生频率；Brier score 也包含区分能力等信息，不能把一个较低分数单独当作校准充分证据。见 [scikit-learn 概率校准文档](https://scikit-learn.org/stable/modules/calibration.html)。

只观察到考生实际报考学校的结果，通常观察不到同一个人报另一所学校会怎样。因此，“推荐使上岸率提升多少”不能靠名单回放直接证明。先验证可观测的门槛、条件结果与风险校准，再讨论推荐效果。

## 9. 建议的落地次序与验收门槛

这是按依赖排序的工作包，不是未经评估的工期承诺。学校扩展速度取决于实际公开资料的完整度。

| 阶段 | 交付物 | 验收标准 |
|---|---|---|
| A：采集可信 | 修复第 8 节 P1；原文快照、字段证据、竞争池定义 | 单校失败不阻断批次；关键事实能定位到原文；未知不冒充 0 或否定 |
| B：最小数据闭环 | 先做 1 所学校 1 个完整竞争池，再扩到 3 所学校、约 6—10 个池；含不同规则与不完整样本 | 入围、结果、名额口径可核对；缺失样本能正确降级；至少一份手工复核报告 |
| C：可用的择校比较 | 分科估分、历史门槛/分布、复试规则敏感性、硬约束与偏好 | 同一项目面对不同考生能解释差异；每条结论带证据，未验证概率不发布 |
| D：情景与历史验证 | 名额/需求/个人发挥情景；年度基线回测 | 截至时点无结果泄漏；展示排序反转条件；复杂模型无增益就保留基线 |
| E：扩大覆盖与自动化 | 10—20 所代表性院校、变更提醒、稳定 API/页面 | 覆盖扩大不牺牲证据完整性；异常可见且能恢复；监控规则与目标年度匹配 |

现有 MySQL 可以继续用；采集可先使用 Python 命令行任务。Redis、RabbitMQ、复杂服务拆分和全国社媒采集的优先级，应由任务量、失败恢复与并发需求决定。没有必要为完成第一份有效择校报告先补齐全部架构。

第一版最有价值的成果是一份可追溯的个人比较报告：少量候选、明确约束、历史位置、复试适配、压力情景、选择反转条件、下一条最值得补查的信息。由这份报告反推采集范围，再扩大系统。
