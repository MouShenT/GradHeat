# 架构、择校与采集方案评审

日期：2026-09-23。范围是方案选择与风险验证，不推进业务编码。结论基于现有代码、官方项目文档及少量真实招生网页；不是规模化性能测试，也未据此推荐具体院校。

## 1. 选型结论

采用“模块化单体 + 独立 Python 采集/分析任务 + MySQL + 原始文件证据库”。先完成离线比较报告，不以 Java API、前端、Redis、RabbitMQ 全部接入作为前置条件。

| 决策 | 建议 | 理由与触发条件 |
|---|---|---|
| 产品 API | 第一轮报告无需 API；已有 Java 维护能力时沿用 Spring Boot 规划 | 语言选择本身不提升数据可靠性。Python 单栈 API 可作为团队主要维护 Python 时的替代，不并行建设两套 API |
| 采集主框架 | 首个小样本沿用 requests/lxml；多站点常态采集优先 Scrapy | 调度、按域限速、去重、重试和中间件是采用框架的理由，不以是否需要 JS 判断 |
| 动态页面 | Playwright 按源启用 | 先验证普通 HTTP 是否缺关键内容；公开接口可稳定访问时单独评估，不默认所有页面开浏览器 |
| 搜索 | Exa/Firecrawl 发现入口和补漏；SearXNG 后备 | 注册来源后直接增量检查官方栏目，不每日重新全网搜同一批学校 |
| 复杂页面 | Firecrawl 可作为人工研究与降级路径 | 保留 URL、采集时间、缓存参数、所用服务；不能让 Markdown 或 AI JSON 单独成为数字事实 |
| HTML 表格 | 原始 HTML + DOM 结构解析 | 保留 rowspan/colspan 和多级表头，再映射字段；先审核再入事实层 |
| PDF | 先判断文本型/扫描型；文本型候选 pdfplumber | 官方说明其更适合机器生成 PDF；扫描型走独立 OCR 试验，保留页图与坐标 |
| OCR/视觉模型 | 暂不锁定引擎 | 用真实中文合并表头、多页名单、低清图片比较后确定；不因演示效果直接全量采用 |
| 消息与缓存 | 先保留设施，暂不强制接入 | 批任务复杂度/并发证明需要后再启用 RabbitMQ；Redis 不做事实或任务唯一存储 |
| 向量库/RAG | 暂不进入数值主流程 | 规则正文检索以后可用；人数、分母、池关系必须来自可审计结构化事实 |

上述是本项目的工程判断。Scrapy 的自动限速、暂停恢复能力有官方支持，但 JOBDIR 只承诺正常停止后的恢复，不是断电不丢任务的业务账本。[AutoThrottle](https://docs.scrapy.org/en/latest/topics/autothrottle.html)、[恢复说明](https://docs.scrapy.org/en/latest/topics/jobs.html)。

PDF 工具边界依据 [pdfplumber 官方 README](https://github.com/jsvine/pdfplumber/blob/stable/README.md)；浏览器按需路径参考 [Playwright BrowserContext](https://playwright.dev/docs/api/class-browsercontext)。框架本身的能力不能证明本项目的字段抽取正确率。

## 2. 真实样本暴露的问题

| 官方样本 | 本次核验 | 架构含义 |
|---|---|---|
| [华中师大计算机学院 2026 复试细则](https://cs.ccnu.edu.cn/info/1056/10516.htm) | Firecrawl 强制实时抓取，HTTP 200，获得规则、复合表头及附件链接 | Markdown 中表头不是平整一行，不能按位置直接猜字段；下载接口为 download.jsp，不能只抓 .pdf 后缀 |
| [湖南大学计算机学院 2026 复试细则](https://csee.hnu.edu.cn/info/1062/13916.htm) | Exa 正文有计划/分数线标题却无数字；进一步实时 HTML 抓取发现正文图片节点 | 页面可读不等于指标完整；必须检测正文图片并单独解析，未完成前明确缺失 |
| [杭州电子科技大学计算机学院 PDF 细则](https://computer.hdu.edu.cn/_upload/article/files/97/ad/6f63bc334e20a27516f24c80bb4d/3de07e5d-ffda-4136-b508-06f43a2b657c.pdf) | Exa 搜索命中原始 PDF 与规则片段；本轮未完整解析 PDF | 仅作为后续 PDF 测试样本，不把搜索片段当作已验证的完整规则 |

前两校规则的计分量纲与处理方式不同；湖大正文还包含面试分组规格化及合格条件。这支持“规则按池、按年度版本化”的设计，不能只存一个复试权重。上述样本用于检验采集结构，尚未逐一核对 11408 目录资格，也不构成择校候选推荐。

本轮未读取名单中的个人明细，未验证 PDF 全页完整率、OCR 精度、批量稳定性或请求耗时。因此当前可下结论是“已识别真实格式差异并确定分层路线”，不能宣称“全国官网已稳定适配”。

## 3. 来源与采集优先级

| 优先级 | 信息 | 首选来源 | 主要用途/陷阱 |
|---|---|---|---|
| P0 | 当年目录、科目、资格、培养方式、校区 | 学校研招办/研究生院、学院目录、研招网 | 先判能否报；同名专业或不同方向可能要求不同 |
| P0 | 统考可用名额及修订、推免接收结果 | 正式计划与调整公告 | 总计划减“拟推免”不是实际剩余名额；不同时间的数不可相减 |
| P0 | 排名池、单科线、复试办法、淘汰条件 | 学院细则与学校办法 | 具体条款与总则联合核验，保留版本 |
| P1 | 入围名单、复试成绩、拟录取及补录 | 学院公告、学校最终公示 | 明细群体要匹配，补录/放弃要留事件；未公开不能推断落榜 |
| P1 | 学费、学制、住宿、培养地点 | 招简、收费/培养公告 | 个体效用与可行性约束，避免只看分数 |
| P2 | 报名人数或阶段报名统计 | 官方公开统计 | 区分累计/确认、统计截止、学校/专业层级；没有就标缺失 |
| P3 | 搜索热度、社媒讨论、经验帖 | 平台与原作者 | 线索与解释假设，不作为名额/资格真值，不先全网采集 |

来源可信度、抓取可靠性、字段抽取准确性、预测价值是四个不同问题。官方发布也可能修订，第三方工具返回成功也可能漏表格。若学校最终公示与学院建议名单不同，应依适用范围与后续修订核对，保留差异，不静默择一。

## 4. 稳定且节省成本的采集流程

1. 人工核准 source registry：学校主体、学院、栏目、文档类型、预期格式、目标年度、抓取频率和模板族。模板共用解析器，学校只配差异；改版后按版本回放。
2. 扫描栏目列表和少量重叠分页，维护已知文章集合。不能因一条旧日期就停止：置顶、补发、排序变化都可能漏数据。定期更深扫描校验索引完整性。
3. 只抓新增/变化正文。支持 ETag/Last-Modified 时做条件请求；不能假定所有校园站正确实现。服务端不支持时用内容哈希，但仍需先下载，不能把去重说成免请求。
4. 保存正文和附件原始字节、最终 URL、请求时间、响应类型及哈希。附件依 Content-Type、文件签名和正文链接识别，不只看扩展名；失败下载不能当成空名单。
5. 按内容路由：HTML 表格 → DOM；文本 PDF → 文本/表格；图片/扫描 PDF → OCR；必要的动态内容 → 浏览器。页面截图用于定位，不替代原始附件。
6. 抽取候选字段并做结构约束：表头路径、列数、跨页重复表头、页码连续性、重复行、人数与已知总计核对。模型只标候选和歧义，不自行填补缺失。
7. 关键事实复核后追加版本。内容变更识别与语义变更分开，浏览次数或栏目装饰变化不触发模型全量重算；仍保留原文版本。
8. 从已审核事实生成决策快照；只重算其依赖受影响的报告。报告保存此前版本，显示已过期或待复核状态。

初始运行参数建议而非测速结论：每域并发 1、请求间隔 2—5 秒，总并发 4；浏览器单任务运行。平时每天检查已登记栏目一次，相关公告窗口可提高到每 6 小时，遇到限流自动延后。具体频率按学校更新规律、访问规则和实测负载调整，不新增自动定时任务。

原文事实的时效要求与搜索缓存不同。关键公告最终核验需直接重取，或对 Firecrawl 指定 maxAge=0；记录实际返回来源和状态。不能用搜索引擎索引时间当官方发布时间。

## 5. 择校决策：可靠性从哪里来

采用“资格硬筛 → 历史位置 → 规则适配 → 偏好权衡 → 情景压力测试”。第一版不以录取概率排序，也不将所谓低热度学校自动定义为洼地。

- 硬筛包括初试科目、报考身份、培养方式、专项资格和不可接受的费用/地域；未知返回待核查。
- 比较的是官方竞争池，不是学校名。录取名单只有成功样本，不能提供所有报考者分母，也不能直接算个人录取概率。
- 用总分和单科范围比较历史门槛，用复试考核结构解释个人适配；同年同卷也需显示群体与规则差异。
- 偏好由用户决定。信息不足时不强行合成一个总分；先保留不被其他候选全面压过的选择，再显示成本、培养价值与风险取舍。
- 名额下降、需求上升、个人发挥偏差等情景必须说明设定来源；没有概率依据只做敏感性分析。展示“何时结论会反转”，不预测必然大小年。
- 最高优先级补查是可能改变当前决策的信息。例如剩余名额未知时先查计划修订，不先扩采几千条社媒帖子。没有概率模型时称“补查优先级”，不伪称精确期望信息价值。

概率模型将来必须有匹配群体的标签、历史截止时间、时间外验证与校准；对推荐提升上岸率的因果结论另行设计验证。当前只确立边界，不宣称已通过这些检验。

## 6. 下一轮验证如何判定可靠与高效

先建 30—50 份人工标注样本，覆盖至少 3 校、HTML 合并表格、正文图片、文本 PDF、扫描 PDF、动态/下载接口、修订公告和缺失情形；这是建议样本量，不是统计充分性保证。逐类公布结果，不能用简单页面的高成功率掩盖难样本失败。

| 指标 | 分母/记录方式 | 决策 |
|---|---|---|
| 来源发现召回 | 人工登记相关公告中自动发现的比例 | 发现差则改栏目与分页策略，不靠换解析模型 |
| 原文完整获取率 | 目标正文及必需附件完整留存数 / 目标数 | HTML 成功、附件失败不能算完整 |
| 关键字段准确率 | 与金标准核对的池、年份、科目、名额、规则 | 任一错误可改变资格/结果时隔离该记录 |
| 错误放行率 | 错误事实仍被标 accepted 的比例 | 试点目标为 0 个已知关键错误放行；不解释成总体零风险 |
| 人工复核成本 | 每池分钟数、每份文档修正数 | 比较端到端成本，不只比抓取耗时 |
| 获取成本 | 请求数、字节、浏览器秒、云额度、重试数 | 固定同一组样本比较不同路由 |
| 新鲜度 | 发现时间减可核对发布时间 | 对回填和时间未知单独列出，不假装精确延迟 |
| 恢复性 | 中断、重复任务、改版回放与证据定位 | 没有丢失且没有重复正式事实才放行 |

试点先让确定性解析与人工校验跑通，再测试 OCR/AI 是否真实降低总成本。后续技术定版以这组基准决定；目前不承诺任何工具达到固定覆盖率或准确率。

## 7. 对现有代码的静态判断

requests/lxml 适合作为试点起点，但现有 net.py 统一重试所有异常、随机 UA、未体现按域共享限速或 Retry-After；出口探测也不能证明目标请求路由及内容完整。现有证据覆盖/覆盖写入问题见 DECISION-REVIEW。这些意味着“方案可行”和“当前实现可靠”不能画等号。

采用稳定、可辨识的请求身份；国内直连作为按源验证后的默认策略，不是不可更改的定律。不要将提高并发和不断重试作为应对错误页面的主要办法。

本轮仅更新方案文档，未安装新框架、修改采集逻辑、运行批量爬取或变更虚拟机服务。
