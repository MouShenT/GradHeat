# 当前架构

浏览器 → Vite / Vue → Java `/api/v1` → Python 内部接口 / RabbitMQ worker → MySQL。Redis 是可重建缓存；MySQL 保存原件、资料版本、任务和院校档案。

Java 负责业务入口、版本一致性、比较档案和消息事务。Python 内部 API 验证专用令牌；共享算法在 `gradheat_core`，不依赖网页服务器。采集 CLI 可脱离聊天、网页和 RabbitMQ 运行。

院校数据通过招生发布版本与独立档案版本关联。社交内容去重后按院校关联，大类多校帖子分别归档。实际搜索保留关键词、时间窗、设备、区域和原始序列，缺值与真实零区分。

单校页面按院校读取并校验该校原件；全市场计算在 MySQL 校验档案原件 SHA 后只传输算法所需字段，避免每次页面请求下载全部讨论正文。投影来自规范原字节，档案版本与算法结果保持一致。

Windows 任务计划程序运行开发管理进程，保持 Vite 5173、Java 18731、Python 18732 及专属 SSH 转发。进程失败恢复，前端热更新。采集持有既有锁，仓库更新不会启动额外批次。

发布先审查完整源码树，再从无数据副本测试与构建。远程只快进；部署使用不可变构建路径，前端保持 Vite，后台按验证后的构建重启。已应用迁移的原字节不改，新增迁移另行编号。
